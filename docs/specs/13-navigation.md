## 3. ルーティングガード

### 3.1 ガードロジック

Root Layout（`app/_layout.tsx`）で以下の条件分岐を実装:

```
認証チェック
+-- 未認証（ゲスト）
|   +-- コミュニティタブ -> アクセス可能（閲覧のみ）
|   +-- その他のタブ -> (auth)/guest-prompt にリダイレクト
|   +-- ログインボタン -> (auth)/login
+-- 認証済み
    +-- onboardingCompleted === false -> (onboarding)/welcome にリダイレクト
    +-- onboardingCompleted === true -> (tabs) にルーティング
        +-- Pro機能 -> subscriber チェック
```

### 3.2 アクセスレベル

| レベル | 対象ユーザー | アクセス可能画面 |
|--------|------------|---------------|
| guest | 未認証 | コミュニティ一覧・詳細（閲覧のみ） |
| authenticated | 認証済み（Free含む） | 全タブ（Pro機能は制限付き） |
| subscriber | Pro課金済み | 全機能アクセス可能 |

### 3.3 判定データソース

| 条件 | データソース | 判定方法 |
|------|------------|---------|
| 認証状態 | Supabase Auth (useAuthStore) | session が null でないこと |
| オンボーディング完了 | profiles.onboarding_completed | true/false |
| サブスク状態 | useSubscriptionStore | EntitlementInfo.isPro |

### 3.3 ガード実装の注意事項

- 認証状態の確認中はスプラッシュ画面（またはローディング）を表示し、画面のちらつきを防止する
- Supabase Auth の `onAuthStateChange` リスナーで認証状態の変化を監視する
- オンボーディング完了状態は profiles テーブルから取得し、Zustand Store にキャッシュする
- ディープリンクからのアクセス時もガードが正しく動作すること

## 5. タブ間遷移

### 5.1 タブ切替時の動作

| 遷移先 | 動作 |
|--------|------|
| チャット | チャット履歴をリフレッシュ（最新メッセージ表示） |
| コミュニティ | Pro判定。Free -> ブラー表示 + ペイウォール誘導、Pro -> AIツイン会話リスト表示 |
| ツイン情報 | 性格データ + 気分トラッキング + OpenClawステータスを最新化 |
| 設定 | プロフィール・サブスク・インスタンス情報を最新化 |

### 5.2 モーダル表示のトリガー

| モーダル | トリガー | 遷移元 |
|---------|---------|--------|
| ペイウォール | Free機能制限タップ、設定「Proにアップグレード」タップ | コミュニティ、チャット、ツイン情報、設定 |
| サブスク管理 | 設定「サブスクリプション管理」タップ | 設定 |
| ツイン会話詳細 | コミュニティの会話アイテムタップ | コミュニティ |
| アカウント削除確認 | 設定「アカウント削除」タップ | 設定 |

## 8. 画面状態一覧（全画面共通）

各画面で以下の状態をデザインする:

| 状態 | 説明 |
|------|------|
| Default | 通常表示 |
| Loading | データ取得中（スケルトン / スピナー） |
| Empty | データなし（イラスト + CTA） |
| Error | エラー発生（メッセージ + リトライ） |
| Offline | ネットワーク未接続（バナー表示） |
| Free | 無料ユーザー向け表示（制限 + アップグレードCTA） |
| Pro | 有料ユーザー向け表示（フル機能） |
