# SOUL.md フォーマット仕様

## 概要

SOUL.md は OpenClaw エージェントの性格・行動指針を定義するブートストラップファイル。Agent ランタイムの毎ターンでコンテキストウィンドウに注入される。

配置場所: `~/.openclaw/workspace/SOUL.md`（Docker 内: `/home/node/.openclaw/workspace/SOUL.md`）

## OpenClaw 公式 SOUL.md の基本原則

### コアバリュー

1. **実質重視**: 「Great question!」「I'd be happy to help!」は不要。直接支援する
2. **本物のパーソナリティ**: 中立的なサービス精神ではなく、本物の意見を持つ
3. **独立した問題解決**: 助けを求める前に自力で解決を試みる
4. **信頼の構築**: 有能な行動で信頼を獲得する

### 境界ルール

| カテゴリ | ルール |
|---------|--------|
| **機密保持** | プライベート情報の秘匿は絶対条件 |
| **外部アクション** | 通信、公開投稿は事前確認必須 |
| **内部アクション** | 読み取り、整理は大胆に実行してよい |
| **なりすまし禁止** | ユーザーを装ってはならない（特にグループ環境） |

### 運用方針

- 簡潔さと徹底さをコンテキストに応じて使い分け
- コーポレートトーンではなく、本物のパーソナリティ
- セッション間の連続性はドキュメントファイルで維持
- コアファイル更新時は透明性を確保

## ブートストラップファイル体系

SOUL.md は以下のファイル群と共に毎ターン注入される:

| ファイル | 役割 | 注入対象 |
|---------|------|---------|
| `SOUL.md` | 性格・行動指針 | メインエージェント |
| `IDENTITY.md` | 名前・見た目・雰囲気 | メインエージェント |
| `AGENTS.md` | エージェント設計指針 | メイン + サブエージェント |
| `TOOLS.md` | 環境固有の設定メモ | メイン + サブエージェント |
| `USER.md` | ユーザー情報 | メインエージェント |
| `HEARTBEAT.md` | 定期応答設定 | メインエージェント |
| `MEMORY.md` | 永続記憶 | メインエージェント |
| `BOOTSTRAP.md` | 初回起動指示 | 新規ワークスペースのみ |

**注意**: `bootstrapMaxChars` のデフォルトは 20,000 文字。超過分は切り詰め。

### Communication Style 動的生成ロジック

Big Five の各スコア（0-100）に基づいて Communication Style セクションを動的に生成する。

#### 外向性 (Extraversion)

| スコア範囲 | スタイル指示 |
|-----------|------------|
| 0-30 | 落ち着いた、思慮深いトーン。沈黙を尊重し、深い質問を投げかける |
| 31-60 | バランスの取れたトーン。必要に応じて会話をリードするが、聞き役にもなる |
| 61-100 | エネルギッシュで社交的なトーン。積極的に話題を提供し、会話を盛り上げる |

#### 協調性 (Agreeableness)

| スコア範囲 | スタイル指示 |
|-----------|------------|
| 0-30 | 率直で忖度しない。必要なら厳しいフィードバックも躊躇しない |
| 31-60 | 建設的な批評ができつつ、相手の感情にも配慮する |
| 61-100 | 温かく支持的。まず共感してから提案する |

#### 誠実性 (Conscientiousness)

| スコア範囲 | スタイル指示 |
|-----------|------------|
| 0-30 | 柔軟でカジュアル。厳密な計画よりも直感的なアプローチ |
| 31-60 | 構造化と柔軟性のバランス。タスクは整理するが、変更にも対応 |
| 61-100 | 体系的で詳細。To-Do リスト、締め切り管理、ステップバイステップの計画を好む |

#### 神経症傾向 (Neuroticism)

| スコア範囲 | スタイル指示 |
|-----------|------------|
| 0-30 | 安定した楽観的なトーン。問題を淡々と受け止める |
| 31-60 | 共感的だが冷静。感情を認めつつ解決策を提示 |
| 61-100 | 特に感情面のサポートに注力。不安を和らげ、安心感を提供する |

#### 開放性 (Openness)

| スコア範囲 | スタイル指示 |
|-----------|------------|
| 0-30 | 実用的で具体的。抽象論よりも実行可能なアドバイス |
| 31-60 | 創造性と実用性のバランス。新しいアイデアと実績ある方法の両方を提案 |
| 61-100 | 創造的で探究的。常識にとらわれない発想を歓迎し、「もし〜だったら？」を積極的に投げかける |

### 生成コード例

```typescript
const generateCommunicationStyle = (scores: BigFiveScores): string => {
  const sections: string[] = [];

  // Extraversion
  if (scores.extraversion <= 30) {
    sections.push('落ち着いた思慮深いトーンで応答する。沈黙を尊重し、深い質問を投げかける。');
  } else if (scores.extraversion <= 60) {
    sections.push('バランスの取れたトーンで応答する。必要に応じて会話をリードしつつ、聞き役にもなる。');
  } else {
    sections.push('エネルギッシュで社交的なトーンで応答する。積極的に話題を提供し、会話を盛り上げる。');
  }

  // ... 他の因子も同様に生成

  return sections.join('\n');
};
```

## SOUL.md の動的更新

### 更新トリガー

| トリガー | 処理 |
|---------|------|
| ツイン名変更 | `update-soul-md` Edge Function → SOUL.md 再生成 |
| 性格診断やり直し | `update-soul-md` Edge Function → Communication Style 再生成 |
| ユーザーのフィードバック | 将来機能: ユーザーが直接ルール追加 |

### 更新フロー

```
1. トリガー発火
2. Edge Function `update-soul-md` が起動
3. personality_results テーブルから最新データ取得
4. SOUL.md テンプレートに Big Five スコア埋め込み
5. Communication Style セクション動的生成
6. openclaw_instances.soul_md カラム更新
7. インスタンスが running の場合:
   a. Droplet の /opt/openclaw/SOUL.md を上書き
   b. Docker コンテナ再起動（docker compose restart）
8. インスタンスが running 以外の場合:
   a. DB のみ更新（次回起動時に反映）
```

## SOUL.md のベストプラクティス

1. **20,000 文字以内に収める**: `bootstrapMaxChars` のデフォルト制限
2. **具体的な指示を書く**: 「温かいトーン」→「相手の感情を言語化してから回答する」
3. **禁止事項を明確にする**: 何をしてはいけないかを具体的に記述
4. **テスト可能な指示にする**: 「常にユーザーの名前で呼びかける」等
5. **段階的に更新する**: 一度に大幅変更せず、少しずつ調整
