# タスク精査チェックリスト

## Phase 1: 仕様書カバレッジ

- [ ] specs/overview.md の全体要件がタスク化されているか
- [ ] specs/features/ の各 AC がタスクに対応しているか
- [ ] specs/api/ のエンドポイントがタスクに対応しているか
- [ ] specs/screens/ の画面仕様がタスクに対応しているか
- [ ] specs/shared/ の横断要件がタスクに反映されているか

## Phase 2: タスク品質

### 各タスクに対して:
- [ ] 動詞で始まるタスク名か（「実装する」「設定する」「テストする」）
- [ ] 参照する仕様書パスが明記されているか
- [ ] 担当 Agent が割り当てられているか
- [ ] 完了条件がテスト可能な形で記述されているか
- [ ] サイズ（S/M/L）が適切か
- [ ] 依存タスク（ブロッカー）が正しく設定されているか

### 完了条件の品質:
- [ ] 数値で計測可能か
- [ ] 再現手順が明確か
- [ ] 境界値が定義されているか
- [ ] エラーケースが含まれているか

## Phase 3: 依存関係

- [ ] 循環依存がないか
- [ ] shared/ 変更タスクが早期に配置されているか
- [ ] DB マイグレーションがフロントエンドより先にスケジュールされているか
- [ ] Edge Function がフロントエンド呼び出し元より先か
- [ ] 並列実行可能なタスクが正しく識別されているか

## Phase 4: Agent バランス

- [ ] Agent 間のタスク量が均等か（±20%以内）
- [ ] ブロッカータスクが1 Agent に集中していないか
- [ ] shared/ 変更を含むタスクにクロスチェックフラグがあるか
- [ ] 各 Agent の担当ディレクトリとタスクの対象ファイルが一致しているか

## Phase 5: リスク

- [ ] 外部サービス依存（DigitalOcean API, RevenueCat）のフォールバックがあるか
- [ ] テストモック/スタブが用意されるタスクがあるか
- [ ] クリティカルパス上のタスクに追加のレビューステップがあるか
- [ ] セキュリティ関連タスク（RLS, 認証, API キー管理）が明示されているか
