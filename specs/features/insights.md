# ツイン情報（Twin Info）仕様書

## 基本情報
- 担当Agent: Agent D (Engagement)
- 関連画面: app/(tabs)/twin.tsx
- 依存する機能: 認証、オンボーディング（性格診断結果）、OpenClawプロビジョニング、課金
- 依存される機能: なし

## 目的
ユーザーのAIツインに関する全情報を統合的に表示する。
性格データ、気分の推移、SOUL.mdの要約、OpenClawインスタンスの状態を1つの画面で確認できる。
データの蓄積を可視化し、AIツインとの関係性の深さを実感させることで解約防止に貢献する。

## ユーザーストーリー
- [ ] ユーザーとして、自分のBig Five診断結果を確認したい。なぜなら自分の性格特性を見返したいから。
- [ ] ユーザーとして、今日の気分を5段階で記録したい。なぜなら日々の感情を簡単にトラッキングしたいから。
- [ ] ユーザーとして、直近7日間の気分の推移を確認したい。なぜなら自分の感情パターンを把握したいから。
- [ ] Proユーザーとして、SOUL.mdのサマリーを確認したい。なぜならAIツインの性格設定を知りたいから。
- [ ] Proユーザーとして、OpenClawインスタンスの状態を確認したい。なぜならAIツインの動作状況を確認したいから。
- [ ] ユーザーとして、性格診断をやり直したい。なぜなら診断結果を更新してAIツインを再調整したいから。

## 受け入れ条件（Acceptance Criteria）

### AC-1: Big Five性格プロフィールが表示される
- Given: 認証済みでオンボーディング完了済みのユーザーがツイン情報タブを開く
- When: 画面がロードされる
- Then:
  - Big Five 5トレイトの棒グラフが表示される（開放性、誠実性、外向性、協調性、神経症傾向）
  - 各トレイトのスコア（0-100）がグラフ上に表示される
  - 性格サマリーテキストが表示される（`personality_results.summary`）
  - 「性格診断をやり直す」リンクが表示される

#### エッジケース
| ケース | 期待される動作 |
|--------|--------------|
| 性格診断未実施のユーザー | オンボーディングにリダイレクト |
| 性格診断結果の取得エラー | エラーメッセージ表示 + リトライボタン |
| 性格診断を複数回実施している | 最新の診断結果を表示 |
| サマリーテキストが非常に長い場合 | スクロール可能または「さらに読む」展開ボタン |

#### テスト観点
- [ ] 正常系: Big Fiveの5トレイトが正しいスコアで表示される
- [ ] 正常系: サマリーテキストが正しく表示される
- [ ] 境界値: スコアが0の場合、グラフが正しく表示される
- [ ] 境界値: スコアが100の場合、グラフが正しく表示される
- [ ] 異常系: 診断結果が存在しない場合のハンドリング

### AC-2: 性格診断のやり直しができる
- Given: ユーザーがツイン情報タブで「性格診断をやり直す」リンクを表示している
- When: リンクをタップする
- Then:
  - 確認ダイアログが表示される（「性格診断をやり直すと、AIツインの性格も変わります。よろしいですか？」）
  - 「はい」をタップするとオンボーディングの性格診断画面に遷移する
  - 新しい診断結果が保存されると、SOUL.mdが再生成される（Proユーザーの場合）
  - 診断結果は `personality_results` テーブルに新規レコードとして追加される（履歴保持）

#### エッジケース
| ケース | 期待される動作 |
|--------|--------------|
| 「いいえ」をタップ | ダイアログが閉じる、画面はそのまま |
| Proユーザーが再診断 | OpenClawインスタンスのSOUL.mdが自動更新される（Edge Function `update-soul-md` 呼出） |
| Freeユーザーが再診断 | 診断結果はDBに保存されるが、OpenClawへの反映はPro課金後 |
| インスタンスが停止中の再診断 | DB更新のみ、次回起動時にSOUL.md反映 |
| SOUL.md更新エラー | 診断結果の保存は成功として扱い、SOUL.md更新は非同期リトライ |

#### テスト観点
- [ ] 正常系: 確認ダイアログが表示される
- [ ] 正常系: 「はい」で性格診断画面に遷移する
- [ ] 正常系: 新しい診断結果が保存される
- [ ] 正常系: Proユーザーの場合SOUL.mdが更新される
- [ ] 異常系: SOUL.md更新エラー時に診断結果は保存される
- [ ] 境界値: 「いいえ」タップで何も起きない

### AC-3: 今日の気分を5段階で記録できる
- Given: 認証済みユーザーがツイン情報タブを開いている
- When: 5つの気分絵文字（great😄/good🙂/neutral😐/bad😢/terrible😫）から1つを選択する
- Then:
  - 選択した気分が `mood_records` テーブル（気分データのSingle Source of Truth）に当日日付で保存される
  - 選択済みの絵文字がハイライトされる
  - 週次気分グラフが即座に更新される

**注:** `mood_records` テーブルが気分データのSingle Source of Truth。`journal_entries` テーブルの `mood` カラムは廃止済み。

#### エッジケース
| ケース | 期待される動作 |
|--------|--------------|
| 当日すでに気分を記録済み | 既存の記録が選択状態で表示される（上書き可能） |
| 日付が変わった直後（0:00） | 新しい日付として未記録状態で表示される |
| ネットワーク切断中に記録 | エラーメッセージ表示、選択状態は元に戻る |
| タイムゾーンが異なるユーザー | ユーザーのタイムゾーン（profiles.timezone）基準で日付判定 |

#### テスト観点
- [ ] 正常系: 5種類の気分がそれぞれ記録できる
- [ ] 正常系: 記録後にUIが即座に更新される
- [ ] 異常系: ネットワークエラー時に選択が元に戻る
- [ ] 境界値: 日付変更境界（23:59 → 0:00）での動作

### AC-4: 気分を変更（上書き）できる
- Given: 当日すでに気分を記録済みのユーザーがツイン情報タブを開いている
- When: 別の気分絵文字を選択する
- Then:
  - `mood_records` テーブルの当日レコードが upsert で上書きされる
  - 新しい気分がハイライトされる
  - 週次気分グラフが即座に更新される

#### エッジケース
| ケース | 期待される動作 |
|--------|--------------|
| 同じ気分を再度タップ | 何も変更されない（不要なAPIコールを防止） |
| 変更中にネットワークエラー | エラーメッセージ表示、前の気分が選択状態に戻る |
| 短時間で連続変更 | デバウンス処理で最後の選択のみ保存 |

#### テスト観点
- [ ] 正常系: 気分の上書きが正常に動作する
- [ ] 正常系: 上書き後に履歴表示も更新される
- [ ] 異常系: 同じ気分の再選択で不要なAPIコールが発生しない
- [ ] 性能: 連続変更がデバウンスされる

| 7日間すべて記録済み | 全日の気分が表示される |
| アプリ初回利用日から7日未満 | 利用開始日以降の日数分のみ表示 |

#### テスト観点
- [ ] 正常系: 7日間の気分が正しく時系列表示される
- [ ] 正常系: 未記録日がグレーアウト表示される
- [ ] 境界値: 全日未記録時の空状態表示
- [ ] 境界値: 全日記録済み時の完全表示
- [ ] 境界値: 利用開始から7日未満の場合の表示

### AC-7: ProユーザーにOpenClawインスタンスのステータスが表示される
- Given: Pro課金済みのユーザーがツイン情報タブを開いている
- When: 画面をスクロールしてインスタンスステータスセクションを表示する
- Then:
  - 現在のステータスがバッジで表示される:
    - `provisioning`: 黄色バッジ「セットアップ中...」
    - `running`: 緑色バッジ「稼働中」
    - `stopped`: グレーバッジ「停止中」
    - `error`: 赤色バッジ「エラー」
  - ステータスは初回読み込み時にfetchし、その後30秒ごとにポーリングで更新される（Twin Infoタブがアクティブ（フォアグラウンド）の場合のみ）
  - 「詳細設定」リンクが表示される（タップで設定画面に遷移）

**ポーリング条件:** Twin Infoタブがアクティブ（フォアグラウンド）の場合のみポーリング実行。タブ切替・バックグラウンド移行時は停止してバッテリー消費を抑制。

#### エッジケース
| ケース | 期待される動作 |
|--------|--------------|
| Freeユーザー | このセクションが表示されない |
| インスタンス未作成 | 「インスタンス未作成」と表示 |
| ステータス取得エラー | 最後の既知ステータスをキャッシュ表示 + 「更新に失敗しました」注記 |
| `error`ステータス | 「詳細設定」リンクに「再起動」サブテキストを表示 |

#### テスト観点
- [ ] 正常系: Proユーザーにステータスバッジが表示される
- [ ] 正常系: 各ステータス（provisioning/running/stopped/error）が正しく表示される
- [ ] 正常系: ポーリングで30秒ごとにステータスが更新される
- [ ] 正常系: 「詳細設定」リンクで設定画面に遷移する
- [ ] 境界値: Freeユーザーに非表示
- [ ] 異常系: ステータス取得エラー時のキャッシュ表示

### AC-8: データの更新がリアルタイムに反映される
- Given: ユーザーがツイン情報タブを表示している
- When: 気分を記録または変更する
- Then:
  - 週次気分グラフが即座に更新される
  - 最新の状態が反映される

#### エッジケース
| ケース | 期待される動作 |
|--------|--------------|
| 日記タブで気分を選択して戻った場合 | 日記の気分データがツイン情報タブにも反映される |
| 別デバイスで気分を記録した場合 | プルダウンリフレッシュまたはタブ切替時にデータ同期 |
| キャッシュと最新データの不整合 | Supabaseからの最新データが優先される |
| 設定画面で性格診断をやり直した場合 | ツイン情報タブに戻るとBig Fiveグラフが更新される |

#### テスト観点
- [ ] 正常系: 気分記録後に履歴グラフが即座に更新される
- [ ] 正常系: タブ切替時にデータが同期される
- [ ] 正常系: プルダウンリフレッシュでデータが更新される
- [ ] 正常系: 性格診断やり直し後にBig Fiveグラフが更新される
- [ ] 異常系: キャッシュと最新データの不整合が正しく解消される

## 画面仕様

### ツイン情報タブ (twin.tsx)

#### レイアウト構成（上から順に）
1. **性格プロフィールセクション**
   - Big Five 5トレイト棒グラフ（開放性、誠実性、外向性、協調性、神経症傾向）
   - 各スコア（0-100）の数値表示
   - 性格サマリーテキスト
   - 「性格診断をやり直す」リンク

2. **今日の気分セクション**
   - セクションタイトル「今日の気分」
   - 5つの気分絵文字 (great😄/good🙂/neutral😐/bad😢/terrible😫)
   - 選択状態のハイライト

3. **週次気分グラフセクション**
   - セクションタイトル「気分の推移（直近7日間）」
   - 横軸: 日付（月/日）
   - 縦軸: 気分レベル（5段階）
   - 各日の気分を絵文字またはカラーポイントで表示
   - 未記録日はグレーアウト

4. **AIツイン情報セクション（Pro限定）**
   - セクションタイトル「AIツインの性格」
   - AIツイン名表示
   - SOUL.mdサマリーテキスト
   - Freeユーザーには「Proにアップグレードして詳細を見る」+ ペイウォールボタン

5. **インスタンスステータスセクション（Pro限定）**
   - セクションタイトル「インスタンス状態」
   - ステータスバッジ（provisioning/running/stopped/error）
   - 「詳細設定」リンク（設定画面への遷移）
   - Freeユーザーには非表示

#### 入力項目
- 気分絵文字選択（5種類）
- 性格診断やり直しリンク（確認ダイアログ経由）
- 詳細設定リンク（設定画面への遷移）
- ペイウォールボタン（Freeユーザー）

#### 表示項目
- Big Five棒グラフ（5トレイト × スコア）
- 性格サマリーテキスト
- 今日の気分（5段階絵文字）
- 週次気分グラフ（直近7日間）
- SOUL.mdサマリー（Pro）
- OpenClawインスタンスステータス（Pro）

#### アクション
- 気分絵文字タップで記録
- プルダウンリフレッシュ
- 性格診断やり直しリンク → 確認ダイアログ → オンボーディング遷移
- 詳細設定リンク → 設定画面遷移
- ペイウォールボタン（Free） → ペイウォール画面遷移

#### 状態遷移
- ローディング → 表示（記録済み/未記録） / エラー表示
- 気分記録: 未選択 → 選択済み → ネットワーク保存中 → 完了
- ステータスポーリング: 初回取得 → 30秒ごとに更新

#### 全状態
| 状態 | 表示内容 |
|------|---------|
| ローディング | スケルトンローディング表示 |
| 正常表示（Free） | 性格プロフィール + 気分記録 + グラフ + アップグレード誘導 |
| 正常表示（Pro） | 性格プロフィール + 気分記録 + グラフ + SOUL.mdサマリー + インスタンスステータス |
| エラー | エラーメッセージ + リトライボタン |
| 空状態（気分未記録） | 気分記録の誘導メッセージ |
| 診断未実施 | オンボーディングへリダイレクト |

### 気分の定義（5段階）

|----|--------|------|
| great | 😄 | とても良い |
| good | 🙂 | 良い |
| neutral | 😐 | 普通 |
| bad | 😢 | 悪い |

## データ仕様

### 使用するテーブル
- `personality_results`: Big Five診断結果
  - `personality_traits`: Big FiveスコアのJSONB (`{"openness": 0-100, "conscientiousness": 0-100, ...}`)
  - `summary`: 性格サマリーテキスト
  - `communication_style`: SOUL.md生成用のコミュニケーションスタイルJSON
- `mood_records`: 気分記録（Single Source of Truth）
  - `user_id`, `recorded_at` (DATE), `mood` (great/good/neutral/bad/terrible)
- `profiles`: ユーザープロフィール
  - `twin_name`: AIツイン名
  - `onboarding_completed`: オンボーディング完了フラグ
- `openclaw_instances`: OpenClawインスタンス（Pro）
  - `status`: インスタンスステータス（provisioning/running/stopped/error）

### 必要なAPI
- Supabase クエリ（personality_results, mood_records, profiles, openclaw_instances）
- Edge Function `update-soul-md`（性格診断やり直し時、Pro）
- Edge Function `health-check-openclaw`（ステータスポーリング、Pro）

### 連携
- 日記機能（journal_entries）の気分データと mood_records を同期
- 設定画面の「性格診断やり直し」機能と同等の処理
- OpenClawプロビジョニングのステータス表示（詳細操作は設定画面に委譲）

### キャッシュ
- Zustand persist、5分間TTL
- ステータスポーリングの最終既知値をキャッシュ
