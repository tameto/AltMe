# ナビゲーション構造 仕様書

## 基本情報
- 担当Agent: Agent A (Foundation)
- ルーティングライブラリ: Expo Router v3
- 関連ファイル: app/_layout.tsx, app/(tabs)/_layout.tsx, app/(auth)/_layout.tsx, app/(onboarding)/_layout.tsx, app/(paywall)/_layout.tsx

## 目的
アプリ全体のナビゲーション構造とルーティングガードを定義する。
認証状態・オンボーディング完了状態に基づいて、ユーザーを適切な画面にルーティングする。

## 2. ルーティングガード（_layout.tsx）

### 2.1 ガードロジック

Root Layout（app/_layout.tsx）で以下の条件分岐を実装する。

```
認証チェック
├── 未認証 → (auth)/login にリダイレクト
└── 認証済み
    ├── onboardingCompleted === false → (onboarding)/welcome にリダイレクト
    └── onboardingCompleted === true → (tabs) にルーティング
```

### 2.2 判定に使用するデータ

| 条件 | データソース | 判定方法 |
|------|------------|---------|
| 認証状態 | Supabase Auth (useAuthStore) | session が null でないこと |
| オンボーディング完了 | profiles.onboarding_completed | true/false |
| サブスク状態 | useSubscriptionStore | EntitlementInfo.isPro |

### 2.3 ガード実装の注意事項

- 認証状態の確認中はスプラッシュ画面（またはローディング）を表示し、画面のちらつきを防止する
- Supabase Auth の onAuthStateChange リスナーで認証状態の変化を監視する
- オンボーディング完了状態は profiles テーブルから取得し、Zustand Store にキャッシュする
- ディープリンクからのアクセス時もガードが正しく動作すること

## 4. タブ間遷移

### 4.1 タブ切替時の動作
| 遷移元 → 遷移先 | 動作 |
|----------------|------|
| 任意タブ → チャット | チャット履歴をリフレッシュ（最新メッセージ表示） |
| 任意タブ → 履歴 | Pro判定。Free → アップグレード誘導、Pro → 日記一覧表示 |
| 任意タブ → 設定 | プロフィール・サブスク・気分データを最新化 |

### 4.2 モーダル表示のトリガー
| モーダル | トリガー | 遷移元 |
|---------|---------|--------|
| ペイウォール | Free機能制限タップ、設定画面「Proにアップグレード」タップ | 日記タブ、洞察タブ、設定タブ |
| サブスク管理 | 設定画面「サブスクリプション管理」タップ | 設定タブ |
| 日記作成 | 日記タブ「+」ボタンタップ | 日記タブ |

## 5. ディープリンク対応

### 5.1 対応するディープリンク
| リンク | 遷移先 | 備考 |
|--------|--------|------|
| altme://chat | (tabs)/index.tsx | プッシュ通知からのチャット起動 |
| altme://history | (tabs)/history.tsx | 日記リマインダー通知からの起動 |
| altme://paywall | (paywall)/index.tsx | プロモーション通知からの起動 |

### 5.2 ディープリンク時のガード動作
- 未認証状態でディープリンクを受信 → ログイン後に目的画面にリダイレクト
- オンボーディング未完了状態でディープリンクを受信 → オンボーディング完了後に目的画面にリダイレクト
