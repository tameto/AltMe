# エラーハンドリング方針 仕様書

## 基本情報
- 担当Agent: 全Agent共通
- 適用範囲: アプリ全体
- 関連ファイル: src/shared/utils/error-handler.ts, src/shared/hooks/use-error.ts

## 目的
アプリ全体で一貫したエラーハンドリングを実現し、ユーザー体験を損なわずに障害に対応する。
エラーの種類に応じた適切なフィードバックとリカバリーを提供する。

---

## 1. ネットワークエラー

### 1.1 WebSocket切断
| 項目 | 仕様 |
|------|------|
| 検知方法 | WebSocket `onclose` / `onerror` イベント |
| 再接続戦略 | Exponential Backoff（初回1秒、最大30秒） |
| 最大リトライ回数 | 10回 |
| UI表現 | インラインバナー「接続が切れました。再接続中...」 |
| 再接続成功時 | バナー非表示、未送信メッセージの再送 |
| 最大リトライ到達時 | バナー「接続できません。タップして再試行」 |

#### Exponential Backoff 計算式
```
delay = min(baseDelay * 2^attempt + jitter, maxDelay)
baseDelay = 1000ms
maxDelay = 30000ms
jitter = random(0, 500)ms
```

### 1.2 API呼出失敗（Supabase / Edge Functions）
| 項目 | 仕様 |
|------|------|
| リトライ回数 | 3回 |
| リトライ間隔 | 1秒、2秒、4秒（Exponential Backoff） |
| リトライ対象 | 5xx系エラー、ネットワークタイムアウト |
| リトライ非対象 | 4xx系エラー（クライアントエラー） |
| 全リトライ失敗時 | ユーザーに通知（Alert.alert またはインライン） |
| タイムアウト | 15秒（Edge Functions は 30秒） |

### 1.3 オフライン検知
| 項目 | 仕様 |
|------|------|
| 検知方法 | NetInfo API（@react-native-community/netinfo） |
| オフライン時のUI | 画面上部にオフラインバナー表示 |
| オフライン時の動作 | ローカルキャッシュ（Zustand persist）からデータ表示 |
| オンライン復帰時 | バナー非表示、データ同期を自動実行 |

## 2. 認証エラー

### 2.1 トークン期限切れ
| 項目 | 仕様 |
|------|------|
| 検知方法 | Supabase クライアントの自動リフレッシュ |
| 対応 | Supabase SDK がリフレッシュトークンで自動更新 |
| ユーザー影響 | なし（透過的に処理） |

### 2.2 リフレッシュ失敗
| 項目 | 仕様 |
|------|------|
| 検知方法 | Supabase `onAuthStateChange` で `SIGNED_OUT` イベント |
| 対応 | ローカル状態をクリアし、ログイン画面にリダイレクト |
| ユーザー通知 | Alert.alert「セッションの期限が切れました。再度ログインしてください。」 |
| データ保護 | ローカルキャッシュは維持（再ログイン後に復元可能） |

### 2.3 認証プロバイダーエラー
| エラー | 対応 |
|--------|------|
| Apple Sign-In キャンセル | 何もしない（ログイン画面に留まる） |
| Apple Sign-In 失敗 | Alert.alert「Appleでのログインに失敗しました。もう一度お試しください。」 |
| Google Sign-In キャンセル | 何もしない（ログイン画面に留まる） |
| Google Sign-In 失敗 | Alert.alert「Googleでのログインに失敗しました。もう一度お試しください。」 |
| メールアドレス重複 | Alert.alert「このメールアドレスは別の方法で登録されています。」 |

## 3. OpenClawエラー

### 3.1 インスタンス未起動
| 項目 | 仕様 |
|------|------|
| 検知方法 | ヘルスチェック API（GET /health）が応答なし |
| フォールバック | Supabase Edge Function 経由でAIチャットを提供 |
| ユーザー通知 | インラインバナー「AI分身を起動中です...」 |
| 起動完了時 | バナーを更新「AI分身が準備できました」→ 自動消去 |

### 3.2 Gateway接続失敗
| 項目 | 仕様 |
|------|------|
| 検知方法 | WebSocket接続がタイムアウト（10秒） |
| フォールバック | Edge Function 経由でAIチャットを提供 |
| ステータス表示 | チャット画面ヘッダーに接続状態アイコン表示 |
| 接続状態 | connected（緑）/ connecting（黄）/ disconnected（赤） |

### 3.3 ヘルスチェック失敗
| 項目 | 仕様 |
|------|------|
| チェック間隔 | 60秒ごと |
| 失敗判定 | 3回連続で応答なし |
| 対応 | error ステータス表示 + 設定画面に「再起動」ボタン表示 |
| 再起動フロー | 設定 → 「AI分身を再起動」→ DigitalOcean API で Droplet restart |

## 4. 課金エラー

### 4.1 購入失敗
| エラー | 対応 |
|--------|------|
| App Store / Google Play 購入エラー | Alert.alert「購入に失敗しました。もう一度お試しください。」 |
| ネットワークエラーで購入中断 | Alert.alert「ネットワークエラーが発生しました。接続を確認して再度お試しください。」 |
| 決済手段無効 | Alert.alert「お支払い方法を確認してください。」 |

### 4.2 ユーザーキャンセル
| 項目 | 仕様 |
|------|------|
| 対応 | 静かにペイウォール画面に戻る（エラー表示なし） |
| ログ | アナリティクスイベント `purchase_cancelled` を送信 |

### 4.3 サブスクリプション復元エラー
| 項目 | 仕様 |
|------|------|
| エラー時 | Alert.alert「購入情報の復元に失敗しました。」 |
| リトライ | 設定画面「購入を復元」ボタンで再試行可能 |

### 4.4 Webhook処理失敗（サーバーサイド）
| 項目 | 仕様 |
|------|------|
| 検知方法 | Supabase Edge Function のエラーログ |
| 対応 | ログ記録 + リトライ（RevenueCat が自動リトライ） |
| ユーザー影響 | 一時的にサブスク状態が未反映の可能性 |
| 回復方法 | アプリ起動時に RevenueCat SDK で最新状態を同期 |

## 5. Edge Function エラー

### 5.1 AI振り返り生成エラー（journal-reflect）
| 項目 | 仕様 |
|------|------|
| タイムアウト | 30秒 |
| エラー時 | 日記本体は保存済み、振り返り欄に「生成に失敗しました」表示 |
| リトライ | 日記詳細画面に「再生成」ボタン表示 |

### 5.2 性格診断分析エラー（personality-analyze）
| 項目 | 仕様 |
|------|------|
| タイムアウト | 30秒 |
| エラー時 | Alert.alert「分析に失敗しました。もう一度お試しください。」 |
| リトライ | 結果画面に「再分析」ボタン表示 |

### 5.3 洞察生成エラー（generate-insight）
| 項目 | 仕様 |
|------|------|
| タイムアウト | 30秒 |
| エラー時 | 洞察エリアに「データを分析できませんでした」表示 |
| リトライ | プルダウンリフレッシュで再生成 |

## 6. UI表現パターン

### 6.1 Alert.alert()（致命的 / ユーザーアクション必要時）
| 用途 | 例 |
|------|-----|
| 認証失敗 | 「ログインに失敗しました。もう一度お試しください。」 |
| 購入失敗 | 「購入に失敗しました。もう一度お試しください。」 |
| セッション切れ | 「セッションの期限が切れました。再度ログインしてください。」 |
| 日記削除確認 | 「この日記を削除しますか？この操作は取り消せません。」 |
| アカウント削除確認 | 「アカウントを削除すると全データが失われます。本当に削除しますか？」 |

### 6.2 インライン表示（非致命的）
| 用途 | UI | 位置 |
|------|-----|------|
| オフライン状態 | バナー「オフラインです」 | 画面上部 |
| WebSocket再接続中 | バナー「再接続中...」 | チャット画面上部 |
| AI応答遅延 | テキスト「少々お待ちください...」 | チャット画面内 |
| データ読み込みエラー | テキスト「データを取得できませんでした」+ リトライボタン | コンテンツエリア |
| OpenClaw接続状態 | アイコン（緑/黄/赤） | チャット画面ヘッダー |

### 6.3 console.error（開発時デバッグ用）
| 用途 | 出力内容 |
|------|---------|
| APIエラー詳細 | エンドポイント、ステータスコード、レスポンスボディ |
| WebSocketエラー | イベント種別、エラーコード、メッセージ |
| Storeエラー | Store名、アクション名、エラー内容 |
| RevenueCatエラー | エラーコード、メッセージ、ユーザーID |

### 6.4 サイレント処理（ユーザーに通知しない）
| 用途 | 処理 |
|------|------|
| ユーザーによる購入キャンセル | ペイウォール画面に戻る |
| Apple/Google Sign-In キャンセル | ログイン画面に留まる |
| アナリティクスイベント送信失敗 | ログ記録のみ |
| プッシュ通知トークン登録失敗 | ログ記録のみ、次回起動時に再試行 |

## 7. エラーログ・モニタリング

### 7.1 ログレベル
| レベル | 用途 | 本番環境 |
|--------|------|---------|
| error | 重大なエラー（認証失敗、購入失敗、データ破損） | 送信 |
| warn | 警告（リトライ発生、フォールバック動作） | 送信 |
| info | 情報（再接続成功、キャッシュヒット） | 送信しない |
| debug | デバッグ（API詳細、State変更） | 送信しない |

### 7.2 エラー情報のフォーマット
```typescript
type ErrorLog = {
  timestamp: string;
  level: 'error' | 'warn' | 'info' | 'debug';
  category: 'network' | 'auth' | 'openclaw' | 'payment' | 'edge_function' | 'ui';
  message: string;
  code?: string;
  userId?: string;
  metadata?: Record<string, unknown>;
};
```

## 8. 検証条件

- [ ] WebSocket切断時にExponential Backoffで再接続されること
- [ ] API呼出失敗時に3回リトライされること
- [ ] 4xxエラーではリトライされないこと
- [ ] トークン期限切れ時に自動リフレッシュされること
- [ ] リフレッシュ失敗時にログイン画面にリダイレクトされること
- [ ] OpenClawインスタンス未起動時にフォールバックチャットが動作すること
- [ ] Gateway接続失敗時にステータスアイコンが正しく表示されること
- [ ] 購入失敗時にAlert.alertが表示されること
- [ ] ユーザーキャンセル時にエラー表示がされないこと
- [ ] Webhook処理失敗時にリトライされること
- [ ] オフライン時にキャッシュデータで表示されること
- [ ] オンライン復帰時にデータ同期が実行されること
- [ ] Edge Function タイムアウト時に適切なフォールバックが動作すること
